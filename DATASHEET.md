# Datasheet — BBO Capstone Query Dataset

*Following the Datasheets for Datasets framework (Gebru et al., 2018)*

---

## 1. Motivation

**Why was this dataset created?**
This dataset was created as part of the Imperial College AI/ML Programme Capstone Project (Modules 12–24). The task requires maximising eight unknown black-box functions using a strict budget of one query per function per week. The dataset documents every input submitted and every output received across ten weeks of the project, providing the evidence base for all optimisation decisions.

**Who created it and for what purpose?**
Created by the project student as both a working optimisation log and a reproducibility record. It supports the core task (finding the maximum of each function) and serves as a transparency artefact for weekly reflection and peer review.

---

## 2. Composition

**What does the dataset contain?**
The dataset has two layers:

- **Initial observations:** 10 pre-provided input–output pairs per function, supplied as `.npy` files at the start of the project (`data/function_N/initial_inputs.npy`, `initial_outputs.npy`).
- **Weekly queries:** One additional input–output pair per function per week, manually submitted via the capstone portal. Ten weeks of queries are currently recorded (Weeks 1–10), giving a total of up to 20 observations per function by the end of Week 10.

**Format and size:**
- Inputs: float vectors in [0, 1]^n (n = 2, 2, 3, 4, 4, 5, 6, 8 for F1–F8)
- Outputs: single scalar float (higher = better for all functions)
- Total observations at Week 10: approximately 20 per function (160 total across all 8 functions)

**Gaps and missing values:**
- F4 has two outlier outputs removed from modelling: Week 2 (−26.59) and Week 3 (−26.07). These remain in the raw log but are excluded from GP training.
- Some early weekly submissions for F1–F3 did not record exact input coordinates in the project log (Weeks 1–3 partial).
- The dataset does not include the internal equations of the black-box functions, which are never revealed.

**Does the dataset contain sensitive information?**
No. All data consists of synthetic numerical inputs and outputs generated by the capstone portal. No personal, financial, or identifiable information is present.

## 3. Collection Process

**How were queries generated?**
Each weekly query was generated through a Bayesian Optimisation (BO) pipeline:

1. Load all historical observations (initial data + prior weekly results)
2. Apply output transformations where needed (log-transform; Yeo-Johnson for F4)
3. Remove known outliers from the GP training set
4. Generate 50,000 candidate points using Latin Hypercube Sampling (LHS), clipped to [0.02, 0.98]
5. Optionally restrict candidates to a trust region (radius r around the all-time best input)
6. Fit a Gaussian Process (Matérn ν=2.5, normalize_y=True, 3 restarts)
7. Score candidates using UCB and EI acquisition functions; select the ensemble winner
8. Check for duplicates (minimum distance 0.015); perturb if too close to a prior submission
9. Apply manual overrides where the GP output contradicts a known data trend

**Time frame:**
Weekly, from Module 12 to Module 21 (Weeks 1–10 at time of this datasheet). Three further weeks remain (Modules 22–24).

**Strategy evolution over time:**
- Weeks 1–3: Broad exploration; SVM region classification tried and discarded (0/8 improved in W3)
- Weeks 4–6: Trust regions introduced; UCB+EI ensemble; function-specific beta values
- Weeks 7–9: Tighter exploitation; per-function recovery/momentum/anchor policies
- Week 10: Peer-informed adjustments: F4 switched to recent-only GP (dynamic landscape hypothesis); F1 and F5 manually overridden based on confirmed data patterns

## 4. Preprocessing and Uses

**Transformations applied:**
- **Log-transform** (signed): applied to outputs where the value range spans many orders of magnitude, to stabilise GP fitting
- **Yeo-Johnson transform**: applied to F4 outputs before GP fitting, due to extreme variance and suspected non-stationarity
- **Outlier exclusion**: F4 Week 2 (−26.59) and Week 3 (−26.07) are permanently excluded from GP training; they remain in the raw log
- **Boundary clipping**: all candidate points clipped to [0.02, 0.98] — boundary corners consistently produced poor results
- **Duplicate perturbation**: if a GP-suggested point falls within distance 0.015 of any prior submission, a small random offset (seed=99, ±0.02) is applied

**Intended uses:**
- Bayesian Optimisation research and teaching
- Demonstrating iterative query strategies under a strict budget
- Studying the effect of trust regions, acquisition function choice, and output transforms on convergence

**Uses that should be avoided:**
- Fitting models that assume stationarity to F4 observations without recency weighting — the landscape may shift over time
- Treating early-week F4 observations as representative of the current function landscape
- Using this dataset to benchmark against standard BO benchmarks (Branin, Hartmann, etc.) — the functions are custom and non-standard
